# Major Cloud Platform Comparison

## Checkpoint 3 – Cloud Provider Comparison

The following comparison summarizes key differences among Amazon Web Services, Microsoft Azure, and Google Cloud.

| Category | Amazon Web Services (AWS) | Microsoft Azure | Google Cloud Platform (GCP) |
|---|---|---|---|
| **Launch Year** | 2006 | 2010 | 2008 – early Google cloud platform services through App Engine |
| **Compute Service** | Amazon EC2 | Azure Virtual Machines | Compute Engine |
| **Storage Service** | Amazon S3 | Azure Blob Storage | Cloud Storage |
| **Networking Service** | Amazon VPC | Azure Virtual Network | Google Cloud VPC |
| **Identity Service** | AWS IAM | Microsoft Entra ID | Google Cloud IAM |
| **Primary Strength** | Broad cloud-service portfolio and mature ecosystem | Microsoft enterprise integration and hybrid-cloud capabilities | Data, artificial intelligence, machine learning, and Kubernetes |
| **Ideal Organizations** | Organizations requiring extensive cloud-service choices and scalable global infrastructure | Organizations heavily using Microsoft technologies and enterprise systems | Organizations emphasizing AI/ML, analytics, Kubernetes, and cloud-native applications |

---

# Analysis Questions

## 1. Which cloud provider offers the broadest range of services?

**Amazon Web Services (AWS)** offers the broadest overall service portfolio among the three providers in this comparison. Its catalog covers computing, storage, networking, databases, security, analytics, AI/ML, IoT, serverless computing, containers, application integration, and many specialized cloud workloads.

## 2. Which provider best integrates with Microsoft technologies?

**Microsoft Azure** is the strongest choice for organizations that already depend heavily on Microsoft technologies. Its integration with Windows Server, Microsoft 365, Microsoft Entra ID, SQL Server, and Microsoft's enterprise-management ecosystem can simplify migration and hybrid-cloud deployment.

## 3. Which provider is strongest in Artificial Intelligence and Kubernetes?

For this comparison, **Google Cloud** is the strongest fit when artificial intelligence, machine learning, and Kubernetes are major priorities. Google Cloud provides Vertex AI for AI/ML workloads and Google Kubernetes Engine for managed Kubernetes, while Kubernetes itself grew from Google's earlier container-management experience.

## 4. Which cloud platform would you personally choose and why?

I would choose **Google Cloud** for a new cloud-native project because I am particularly interested in artificial intelligence, data engineering, and containerized applications. Its combination of Compute Engine, Cloud Storage, Vertex AI, and Google Kubernetes Engine would allow me to explore both traditional cloud infrastructure and modern AI-focused architectures.

---

## Comparison Summary

There is no single cloud platform that is automatically the best solution for every organization. AWS provides exceptional service breadth, Azure is highly suitable for Microsoft-centered environments, and Google Cloud is especially attractive for data, AI/ML, Kubernetes, and modern cloud-native development.

The final platform should therefore be selected by matching technical capabilities with the organization's existing systems, budget, workforce skills, performance requirements, availability requirements, and long-term business goals.

# Checkpoint 5 – Equivalent Cloud Services

Although AWS, Azure, and Google Cloud use different product names, many services perform similar cloud-computing functions.

| Service Category | AWS | Microsoft Azure | Google Cloud |
|---|---|---|---|
| **Virtual Machine** | Amazon EC2 | Azure Virtual Machines | Compute Engine |
| **Object Storage** | Amazon S3 | Azure Blob Storage | Cloud Storage |
| **Identity Management** | AWS IAM | Microsoft Entra ID | Google Cloud IAM |
| **SQL Database** | Amazon RDS | Azure SQL Database | Cloud SQL |
| **Kubernetes** | Amazon EKS | Azure Kubernetes Service (AKS) | Google Kubernetes Engine (GKE) |

## Service Mapping Notes

### Virtual Machines

**Amazon EC2**, **Azure Virtual Machines**, and **Compute Engine** allow organizations to create configurable virtual servers in their respective cloud environments.

### Object Storage

**Amazon S3**, **Azure Blob Storage**, and **Cloud Storage** provide cloud object storage suitable for application files, backups, media, archives, and datasets.

### Identity Management

**AWS IAM**, **Microsoft Entra ID**, and **Google Cloud IAM** provide technologies for controlling access to cloud resources, although each provider implements identity, roles, policies, and permissions differently.

### SQL Databases

**Amazon RDS**, **Azure SQL Database**, and **Cloud SQL** provide managed relational database capabilities. Exact supported database engines and management features vary among providers.

### Kubernetes

**Amazon EKS**, **Azure Kubernetes Service**, and **Google Kubernetes Engine** provide managed Kubernetes capabilities that reduce the amount of Kubernetes control-plane infrastructure that customers must operate themselves.
